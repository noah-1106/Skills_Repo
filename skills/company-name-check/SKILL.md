# 公司核名（字号查重）

## 何时用

- 起完公司名，要判断"能不能过工商核验"
- 一次拿到 20+ 候选名，需要批量初筛
- 判断某字号（或含某字符串）是否已被占用
- 品牌改名前的可行性预判

**不用时**：查商标（走商标检索）、查单个企业工商信息（走企业信用查询）。

---

## 两个通道怎么选

| 通道 | 覆盖 | 登录 | 接口 |
|---|---|---|---|
| A 全国 · 总局开放查询 | 全国，但收录很窄（实测「蓝宇」仅 1 条），只能做弱初筛 | 免登录 | `POST http://wsdj.samr.gov.cn/saicmccx/query/home` |
| B 北京 · e 窗通开放查询 | 北京，判别力强（实测「蓝宇」209 条） | 需登录会话 | `POST https://ect.scjgj.beijing.gov.cn/wsdj/mckf/es/getList.do` |

默认顺序：先 A 低成本初筛 → 再 B 精筛。只做北京业务时可直接用 B。

## 通道 A：全国总局开放查询（免登录）

```bash
python3 scripts/check_national.py 靛穹纪 萤穹纪 --trade 科技 --out national.json
```

实现要点（脚本已内置，供排障时对照）：

1. `GET http://wsdj.samr.gov.cn/saicmccx/`，正则取 `id="token" value="..."` 的 token
2. `POST /saicmccx/query/home`，表单参数：`pNameDistinct`（区划，留空）、`pNameSymbol`（字号）、`pNameTrade`（行业）、`token`
3. 响应 `code:"200"` 且 `result.NAME_LIST.checkResult` 为空数组 = 无近似
4. **token 是链式的**：每次响应返回新 token，下一次必须用新的
5. 返回「点击太快了，请您再试」= 限流，sleep 6s 后重新取 token 再试
6. 单并发、每次间隔 2.4s 左右，避免触发风控

## 通道 B：北京 e 窗通开放查询（需登录）

```bash
python3 scripts/check_beijing.py 蓝穹星汉 蓝穹星曜 --profile /tmp/ect-chrome --trade 科技 --out beijing.json
```

### 环境准备（关键）

需要一个**已登录的 Chrome profile**，两种来源：

- **复用已登录的浏览器配置目录（推荐）**：任何带登录态的 Chrome user-data-dir 都可以，
  例如某些 Agent 平台会把内嵌浏览器分区放在
  `~/Library/Application Support/<app>/Partitions/<partition>/`（macOS 示例），把它复制成 `<profile>/Default/` 结构即可
- **用户自己 Chrome 登录后**：直接指定其 profile 路径

### 流程

1. `launch_persistent_context(user_data_dir=<profile>, channel="chrome", headless=True)`
2. 打开 `https://ect.scjgj.beijing.gov.cn/wsdj/mckf/` 建立页面上下文
3. `GET /wsdj/mckf/system/getVerifyCode.do` 取验证码（**必须与提交同一个 context**，session cookie 不落盘）
4. 验证码是**算术题**（如 `64+4`，答案是 68），tesseract 识别算式 → 计算 → 提交
5. 页面内 `fetch` 提交（`withCredentials` 自动带上）：参数 `entTra`（字号）、`nameInd`（行业）、`category`（留空）、`verifyCode`、`pageNum`、`pageSize`
6. 响应 `code:"0000"` 为查询成功，`totalNum` 即命中数；非 0000 多为验证码识别错，换新图重试

### 验证码处理

- 图片尺寸约 59×20，放大 6–12 倍 + 多档阈值 + psm 7/8/13
- 白名单 `0123456789+-xX*/=?`
- 识别结果按 `(\d{1,3})([+\-*/])(\d{1,3})` 解析后计算
- **不要**把它当 4 位数字读——这是最容易错的地方（答案通常 2–3 位）

| 腾讯 | 33 |
| 阿里巴巴 | 11 |
| 蓝宇 | 209 |

**总局通道**（覆盖明显更窄，只适合弱初筛）：

| 对照组 | 实测命中 |
|---|---|
| 腾讯 | 0 |
| 阿里巴巴 | 0 |
| 蓝宇 | 1（中天蓝宇科技有限公司） |

**同一个「蓝宇」：北京 209 条，总局 1 条。** 说明总局开放库收录范围很有限，
它的「0 条」几乎不构成任何证据；北京通道才有判别力。

任一对照片区全为 0（北京通道下）→ 通道或参数有问题，**整批结果作废**。

## 判读规则（比结果本身更重要）

1. **匹配方式是字符包含**：0 条 = 库里没有企业名包含这个字符串
2. **0 条 ≠ 工商必过**：工商还会判读音近似、字形近似；开放库覆盖不全（实测原公司名都可能查不到）
3. **「已占用」有明确证据才算数**：同一名字重试仍返回同样命中数，才判淘汰
4. **商标是另一道闸**：字号过了也要查第 9/35/42 类商标
5. **含高危词根的整族都要警惕**：如「蓝宇」本字 209 条，含此二字的名字即使查到 0 也不建议用

## 第三层：品牌 / IP 重名（必须与字号核验分开标注）

**为什么单列**：字号核验查的是市场监管局的名称库，商标归知识产权局管，两套权利互不相通。
字号核验通过 ≠ 品牌能用。实测案例：

| 字号 | 品牌事实 | 后果 |
|---|---|---|
| 蓝宇 | 浙江蓝宇数码科技股份有限公司（上市 301585），持有 7 件商标 | 字号、商标双拦截 |
| 星环 | 星环信息科技（688031），品牌 Transwarp | 字号能过，商标仍冲突 |

**三步法**（顺序不能反）：

1. **权利人内部商标库**——最准。集团/公司自己的商标台账，直接问法务或品牌部
2. **本地词库扫描**（快，只拦已知强品牌）：
   ```bash
   python3 scripts/brand_scan.py --json 核验结果.json --out brand_scan.json
   ```
3. **官方商标网按类检索**（终判，唯一有法律效力的来源）：
   - 入口：`https://sbj.cnipa.gov.cn/trademark-query` → 「我接受」→「进入查询」
   - 检索子系统（`wcjs/wssq.sbj.cnipa.gov.cn`）对脚本请求返回 403（WAF），必须用真实浏览器
   - **近似查询 / 综合查询需要 CNIPA 账号**（企业实名注册）；商标公告走统一身份认证 `sso.cnipa.gov.cn`
   - 按第 **9 / 35 / 42** 类精查（科技公司常涉三类），记录：注册号、权利人、类别、状态、专用权期限
   - 官方数据滞后、仅供参考，**最终以商标局查询结果与代理机构意见为准**

> ⚠️ 公开搜索引擎（百度/必应）只能作为**线索来源**，用来发现"可能有权利人"，
> 不能作为判定依据，也不写进结论。要判定必须回到官方检索。

**官方链路实测记录**（2026-11）：

| 站点 | 脚本直连 | 说明 |
|---|---|---|
| `sbj.cnipa.gov.cn`（主站） | https 200 | 可读页面 |
| `/trademark-query` | 200（真实 Chrome 可开） | 有「我接受 / 进入查询」 |
| `wcjs / wssq / tzwh / pub.sbj.cnipa.gov.cn` | **403** | WAF 拦截非浏览器，需真实浏览器 + 登录 |
| 商标公告 | 302 → `sso.cnipa.gov.cn` | 走 CNIPA 统一身份认证，需账号 |

**判定分三档**（不要一刀切）：

| 档位 | 含义 | 动作 |
|---|---|---|
| 🚩 高置信冲突 | 明确权利主体，跨类也可能受保护 | 回避，或先取得授权 |
| ⚠️ 通用词命中 | 词本身通用（星辰、星海、星际），商标分散在多类 | 按类别检索后再定，不必然冲突 |
| 🔐 集团自有 | 权利人是自己体系（如蓝标） | 走内部授权确认，可用 |

**维护词库**：`references/brand-watch.json`。只收「有明确权利主体」的词，不收通用形容词；
新发现的品牌冲突案例要回写进去，下次自动拦截。

## 执行坑清单

| 坑 | 处理 |
|---|---|
| shell 60 秒超时 | `nohup` 后台跑 + 轮询日志；30 个名字约 2–3 分钟 |
| Chrome 起不来 `ProcessSingleton` | `pkill -f "<profile>"` + `rm -f <profile>/Singleton*` |
| 会话丢失 | 取验证码和提交必须在同一个 persistent context 内 |
| 总局接口限流 | 单并发 + 2.4s 间隔 + 换 token 重试 |
| 验证码频繁识别错 | 换新图重试，单名最多 15 轮；记录 tries 便于追溯 |

---

## 输出规范

1. JSON 全量存档：`{字号: {status, totalNum, nameList, tries}}`
2. 主表列：**`字号 | 字号核验 | 品牌/IP | 综合判定`**（两列必须分开，不能合并成一个"能不能用"）
3. 文档必须写清：数据源、匹配方式、对照组、局限声明
4. 字号核验分级：✅ 推荐（0 条且无高危字）/ 🟢 可申报 / 🟡 中高（含高危同音字）/ 🟡 高危近似 / ❌ 已占用
5. 品牌/IP 分级：🚩 高置信冲突 / ⚠️ 通用词待核 / 🔐 集团自有需授权 / — 无命中
