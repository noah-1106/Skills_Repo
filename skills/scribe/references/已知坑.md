# scribe Skill 已知坑（真实实测记录）

> 2026-08-25 Skill 化实测记录。每条都是实际踩过确认的。

## API / 参数

1. **diarize 是 query 参数不是 form 字段**——FastAPI 里 `diarize: str = Query("false")` 才正确绑定；没包 Query/Form 的普通参数会被当 query，form 里传了也收不到（实测收到默认值 'false'）。客户端传 `?diarize=true`。
2. **FastAPI 对表单 bool 解析不可靠**——"true" 字符串不保证转 True。用字符串参数 + 宽松解析：`str(diarize).lower() in ("1","true","yes","on")`。
3. **下载 URL 是相对路径**（`/api/download/...`）——客户端要拼 `http://localhost:{port}`。

## 环境 / 依赖

4. **Python 3.9 不支持 `dict | None` 注解**——所有 py 文件顶部必须 `from __future__ import annotations`（scribe.py 曾因此 TypeError）。
5. **CAM++ "Loading remote code failed: model, No module named 'model'" 是无害警告**——funasr 尝试加载 remote code 失败后回退内置模型类，实测 campplus_cn_common.bin "All keys matched successfully" + "CAM++ 声纹模型加载完成 0.4s"，模型真实可用。别被警告吓到去修。
6. **funasr 1.4.2 → 1.4.3 兼容**：SenseVoice/FSMN-VAD/CAM++ 三个模型在 1.4.3 均正常加载。
7. **模型目录必须完整**（configuration.json/config.yaml/model.pt/campplus_cn_common.bin 等）——缺文件会导致 AutoModel 加载异常或 remote code 失败真出错。

## 转写质量

8. **SenseVoice 对英文词偶发不准**——"AI" → "爱"（单字母/短英文词是弱点）。重要英文术语建议人工/LLM 校对（与 xhs-dl 的 ASR 教训同源：ASR 对英文生僻词不可靠，画面 OCR/校对兜底）。
9. **TTS 合成音频声纹区分度低**——用 macOS `say` 生成的两个不同声音（Tingting/Meijia）被 CAM++ 归为同一说话人（相似度 > 0.45）。真人双说话人音频原 scribe 实测聚类全对（门限 0.45 裕度大）。**测试 diarize 用真人音频，别用 TTS**。

## 运行 / 部署

10. **服务重启要 pkill -f "scripts/server.py"**——start.py --detach 不检测端口占用，旧进程不杀会端口冲突且新代码不生效。
11. **首次模型加载 3-15 秒**——health ok 之前调 /api/transcribe 会 503，客户端 ensure_server 要轮询等就绪。
12. **环境钉桩**：TMPDIR/MODELSCOPE_CACHE/HF_HOME/XDG_CACHE_HOME 钉到 skill 内 data/（在 import fastapi/funasr 之前设置，server.py 顶部已有）——上传临时文件/模型缓存不写系统盘。
13. **磁盘满**：上传流式落盘（1MB/块）+ 507 中文报错（原 scribe 踩过系统盘满的坑）。

## 跨平台

14. **Mac（Apple Silicon）已实测**；Windows 代码层兼容（setup.py 重建 venv、funasr 支持 Windows、纯 CPU），待真机验证后再标"可用"。
15. **ffmpeg 系统依赖**（音频解码）：Mac brew install ffmpeg / Windows 官网装。服务端 _resolve_decoder 兜底链：内置 bin/ffmpeg → 系统 ffmpeg → afconvert(macOS)。
