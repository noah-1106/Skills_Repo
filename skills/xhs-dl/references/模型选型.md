# ASR 模型选型记录

> 2026-08-25 多轮实测结论。当前**唯一主模型：paraformer-bilingual int8（224MB）**。

## 对比表（同一段 183 秒 GitHub 周榜音频，英文工具名密集 = 最严苛考题）

| 模型 | 体积 | 英文工具名识别 | 中文 | RTF | 结论 |
|---|---|---|---|---|---|
| **paraformer-bilingual int8** ✅ | 224MB | **优秀**：github/agent/codex/mcp/kv缓存/salesforce/playwright 全对；"cloud code"（Claude Code） | ✅ 流畅 | 0.058 | **选定为默认** |
| zipformer-zh-14M int8 | 24MB | ❌ 全灭：markdown→"吗当"、Claude Code→"克劳克扣"、Apple Silicon→"爱否斯利肯" | ✅ 干净 | 0.016 | 纯中文极速备选（已删） |

| sense-voice int8 | 226MB | 🟡 英文形态对（OPEN AI/APPLE SILICON 对），但 Claude Code→"LOS COD" | ✅ 流畅带标点 | 0.086 | 可用但英文略逊（未长期采用） |
| FireRedASR2 CTC int8 | 739MB | - | - | - | 太大排除 |
| FunASR-Nano | 947MB | - | - | - | 太大排除 |

## 为什么 paraformer 胜出

- **你的核心场景是 AI 资讯收藏**（GitHub 周榜、工具介绍）——价值全在英文工具名里。zh-14M 会把 "Claude Code" 转成 "克劳克扣"（无法搜索），paraformer 转成 "cloud code"（可读可搜）。
- 代价：体积 24→224MB（仍比 scribe 方案 2GB 小 4 倍多）、转写 183s 音频从 2.8s → 11s（完全可接受）。

## API 要点

```python
import sherpa_onnx
rec = sherpa_onnx.OfflineRecognizer.from_paraformer(
    paraformer="models/paraformer-bilingual/model.int8.onnx",
    tokens="models/paraformer-bilingual/tokens.txt",
    num_threads=2, provider="cpu",
)
stream = rec.create_stream()
stream.accept_waveform(16000, samples_float32_normalized)
rec.decode_stream(stream)

```

## 已淘汰模型的教训

- **sherpa-onnx 的 whisper 离线实现有 30 秒硬限制**——长音频直接截断+乱码，别选
- **双语流式 zipformer（bilingual-zh-en）有字重复伪影**——greedy 和 modified_beam_search 都一样，别选
- 下载模型用 **hf-mirror.com**（huggingface.co 直连在国内超时）

## 2026-08-25 补充实测：生僻工具名才是真实考题（paraformer 不达标 → 画面 OCR 兜底为正解）

对同一条 183s「GitHub 周榜」视频（10 个当周新项目，**密集生僻工具名**）做全量实测，结论修正：

### paraformer-bilingual 在这条视频上的实际表现

- 常见词（github/agent/codex/mcp/salesforce/playwright）：✅ 全对
- **生僻/新项目工具名：大面积音译错乱**（这正是 AI 资讯收藏的核心价值，错 = 无法搜索/引用）：

| 真实工具名 | paraformer 转写 | 画面 OCR |
|---|---|---|
| MoneyPrinterTurbo | "tap scturb o" ❌ | ✅ harry0703/MoneyPrinterTurbo |
| public-apis | "public apiice" ❌ | ✅ public-apis/public-apis |
| OpenViking | "open working" ❌ | ✅ volcengine/OpenViking |
| cordis | "cordiice" ❌ | ✅ cordiverse/cordis |
| omarchy | "o m k i i" ❌ | ✅ basecamp/omarchy |
| modular | "w i k e i…mark c c p" ❌ | ✅ modular/modular |
| plugins | "curstpluggins" ❌ | ✅ cursor/plugins |
| omlx | "o m x" ❌ | ✅ jundot/omlx |

中文也有噪声："github 乐榜"（热榜）、"办公系疼"、"优度能平" 等。

### 最终结论（三层）

1. **换 ASR 模型治标不治本**——生僻工具名是"词表外词"，whisper 一样会按发音瞎拼（中英混合更是 whisper 老毛病）。**别再试其他模型**
2. **正解 = 画面 OCR 兜底**：这类 AI 资讯视频，博主几乎都会在屏幕上展示 GitHub 仓库页（项目名/作者/star/描述白纸黑字），抽帧 OCR 100% 权威。xhs.py 已实现：**有口播也抽帧（首帧 + 每 15s 一帧）**，与 ASR 双通道互补
3. **ASR + OCR 分工**：ASR 负责"博主说了什么"（叙事/观点/语气），OCR 负责"画面里写了什么"（工具名/star 数/仓库全名）——两个都不完美，合起来才完整
