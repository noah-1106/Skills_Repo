# 已知坑（真实实测记录）

> 每条都是实际踩过并确认的，别再重新踩。

## 抓取与解析

1. **yt-dlp 对图文笔记报 "No video formats found" 是正常的**（stdout 为空）——图文没有视频流，不是 bug。程序会自动走页面解析路径。
2. **`__INITIAL_STATE__` 是非标准 JSON**——页面里的 JS 对象含 `undefined` 等非法字面量，直接 `json.loads` 会报 "Expecting value"。必须用 yt-dlp 自带的 `from yt_dlp.utils import js_to_json`（或正则替换 `:undefined` → `:null`）。
3. **对象截取必须括号配对扫描**——用正则 `\{.*?\}` 贪婪匹配会把对象后面的 `redMoji` 等后续 JS 吞进来，报 "Extra data"。要从 `__INITIAL_STATE__=` 起点做括号深度计数，找到真正闭合的 `}`。
4. **原图下载不带 Referer 会失败**——`sns-webpic-qc.xhscdn.com` 要求 `-H "Referer: https://www.xiaohongshu.com/"`，否则 403/空文件。
5. **视频 CDN 直链有时效性**（几小时到几天）——`--dump-json` 拿到直链后要**立即**拉音频，不能存着稍后用。

## ASR（sherpa-onnx + paraformer）

6. **`accept_waveform` 要 float32 归一化([-1,1]) 采样**——传 int16 原始整数会被当成巨大振幅，输出乱码。`np.frombuffer(raw, dtype=np.int16).astype(np.float32) / 32768.0`。
7. **paraformer 用 `OfflineRecognizer.from_paraformer(paraformer=..., tokens=...)`**——参数名是 `paraformer` 不是 `model`；结果在 `stream.result.text`（不是 `get_result(stream)`，那是流式模型的）。
8. **短音频/纯音乐会偶发 onnxruntime 报错**（ConstantOfShape / Loop node）——"无语音"视频的正常边界，已 try/except 兜底返回空文本 → 自动走 OCR。**不是 bug，别去修**。
9. **sherpa-onnx 的 whisper 离线实现只支持 30 秒内音频**——长音频直接截断+乱码。别选 whisper。

## OCR（ocrmac / macOS Vision）

10. **ocrmac 必须装进 .venv**——xhs.py 被 venv 引导后跑在 .venv 的 Python 里；只装系统 Python 会导致 OCR 静默返回空字符串（不报错）。安装：`.venv/bin/pip install ocrmac`。
11. OCR 是 macOS 专属（Vision 框架），Windows/Linux 上 `from ocrmac import ocrmac` 会 ImportError → 已捕获返回空，不影响主流程。
    **Windows 替代方案（双平台原则）**：Windows 系统级 OCR 是 `Windows.Media.Ocr`（WinRT API，Win10/11 内置），Python 封装 `winrt-Windows.Media.Ocr`——与 macOS Vision 同级、离线、中文需系统装中文语言包。若要在 Windows 启用 OCR，在 `ocr_image()` 加平台分支即可（~30 行）。

## 环境

12. Python 3.9 需要 `from __future__ import annotations`（`str | None` 语法 3.10+ 才有）。
13. macOS 系统 CLT 的 python3 可能缺 ensurepip（`python3 -m venv` 失败）——需要完整版 Python（brew/python.org）。
14. `.venv` 绑定 CPU 架构（arm64/Intel 二进制不通）——换机器重跑 `setup.sh`，模型和代码通用。

## 平台/工具

15. yt-dlp 2025.10.14+ 原生支持小红书（旧知识"不支持"已过时）；xhs-cli（jackwener）read 命令有 bug（manifest.json），别用。
16. 抖音（douyin）反爬比小红书严一个量级：yt-dlp 卡在 msToken 风控（Chrome cookie 能读但缺 msToken），需专门工具（f2/TikTokDownloader）——xhs-dl 暂不接抖音。

## 画面 OCR 兜底（2026-08-25 新增）

17. **生僻工具名/项目名 ASR 必错，别指望换模型**——paraformer 把 MoneyPrinterTurbo→"tap scturb o"、OpenViking→"open working"（词表外词，whisper 也一样会瞎拼）。**正解是抽帧画面 OCR**：这类 AI 资讯视频画面几乎都是 GitHub 仓库页（项目名/作者/star 白纸黑字），OCR 100% 权威。已在 xhs.py 实现：有口播也抽帧（首帧 + 每 15s 一帧），实测 183s 视频 14 帧全命中、工具名全对。
18. **抽帧用远端 seek（ffmpeg -ss URL），无需下载整片**——小红书 CDN（xhscdn）支持 range 请求，每帧 1~3 秒。帧图片用完即删（临时目录 `out/_frames/`）。
19. **OCR 噪声处理**：GitHub 页面 OCR 会把无关文本一起读进来（如 "macOS/Windows"、"github/ISSUE_TEMPLATE" 会被 repo 正则误判）——资源线索的 repo 列表只需"人工可辨"，不用过度清洗；AI 提炼时按上下文过滤。
20. **有口播视频处理耗时从 5s 级升到 ~20s**（ASR ~11s + OCR ~10s）——这是"工具名权威性"的必要代价，可接受；纯图文/无口播视频不受影响。
